Modding

A short note on how the mod system works today. The code is src/content/mods.{h,cpp}; the built-in catalog of downloadable mods is src/scripts/mods.js.

What a mod is

A mod is a zip archive with the .sgx extension, or a plain folder with the same layout. Its id is the file name without the extension (or the folder name). A folder mod can carry scripts and sounds, not an image pack. A mod has no manifest: the description, version and author shown in the Mods window come from the catalog in mods.js, if the id is listed there.

Where mods live

  • By default the game looks in mods/ inside the Pharaoh data directory.
  • --mods PATH replaces that folder (a relative path is taken from the working directory).
  • Mods are switched on and off in the Mods window; the enabled ids are stored in the config key gameopt_enabled_mods.

What a mod can change

  • Scripts. Every *.js in the archive runs when the mod is mounted. A file with the same path as a built-in script (for example building/well.js) is loaded instead of the built-in one on every later import. Configs are scripts too, so a mod can change building and figure parameters.
  • Sounds. *.wav, *.mp3, *.ogg with the same path as a speech file replace it.
  • Images. An image pack named after the mod (<id>.js inside the archive describes its groups).

Order and conflicts

Mods are sorted by id (case-insensitive) and applied in that order. When two enabled mods ship the same file, the mod whose id sorts later wins, whichever was enabled first; the log shows [mods] conflict <path>: <winner> overrides <loser>. To make a mod win, give it an id that sorts later. Switching a mod off rebuilds the script VM without it.

If a mod's script fails to parse or throws (while loading or later, from one of its handlers), the mod is marked broken: the Mods window shows [ERR], the log has [mods] <id> is broken, and the script VM is rebuilt without it. The rest of the game's scripts keep running. Switch the mod off and on again to retry it.

Replacing a config object in a script replaces it whole: fields the mod leaves out become zero. To change one field, assign it, e.g. building_well.max_service = 2, in a new file of the mod.
